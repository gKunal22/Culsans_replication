# Culsans replication

Replication of **Culsans: An Efficient Snoop-based Coherency Unit for the CVA6 Open Source RISC-V
application processor** (Tedeschi et al., DSD/SEAA 2024 Works in Progress,
[arXiv 2407.19895](https://arxiv.org/abs/2407.19895)) in simulation and Vivado synthesis.

The authors' RTL is used unchanged, as a git submodule (`culsans/`, pinned to
`pulp-platform/culsans@a3d7416`). Everything this repository changes or adds is listed in
[ASSUMPTIONS.md](ASSUMPTIONS.md), and every changed source file is generated by
[scripts/make_overlays.py](scripts/make_overlays.py) into `build/overlay/`, never edited in place.

## Layout

| Path | What it is |
| --- | --- |
| `culsans/` | Authors' repository (submodule): CCU, coherent CVA6, LLC, SoC top, tests |
| `ASSUMPTIONS.md` | Every gap in the paper and the value we chose |
| `scripts/` | File-list generation, overlays, ELF to hex, regression runner |
| `sim/tb/tb_culsans.sv` | One testbench for both XSim and Verilator |
| `sim/xsim/run_xsim.tcl` | Vivado (XSim) runner |
| `sim/common/` | No-op stand-ins for the authors' simulation-only loggers |
| `sw/` | Bare-metal build for the 2-core system (`sw/common` = 2-core startup code) |
| `sw/bench/` | Splash-3 bare-metal port: runtime (`rt/`), build script, benchmark list and inputs |
| `synth/synth_culsans.tcl` | Vivado synthesis of the authors' FPGA top (Genesys 2 part) |

## Setup (Ubuntu on WSL2)

Clone the repository **onto the Windows drive** so that Vivado on Windows can read the same files,
for example `C:\work\culsans_replication` (`/mnt/c/work/culsans_replication` in WSL):

```bash
sudo apt-get install -y git make python3 gcc-riscv64-unknown-elf picolibc-riscv64-unknown-elf
cd /mnt/c/work
git clone https://github.com/gKunal22/Culsans_replication.git culsans_replication
cd culsans_replication
make setup      # fetches the authors' sources (about 200 MB) and writes build/filelists/
make sw         # builds build/sw/integration/*.hex
```

## Simulate in Vivado (XSim, Windows)

Open a "Vivado 2026.1 Tcl Shell" (or a Command Prompt with Vivado's `settings64.bat` applied):

```bat
cd C:\work\culsans_replication
vivado -mode batch -source sim/xsim/run_xsim.tcl -tclargs build/sw/integration/read_cache_share.hex
```

The first run creates `build/xsim/proj` and compiles everything; later runs only simulate.
A passing program prints `[tb] EXIT code=0 cycles=N` and `*** SUCCESS ***`; the full log is
`build/xsim/<test>.log`.

## Synthesize in Vivado (Windows)

After `make setup` in Ubuntu, open a Windows Command Prompt in the repo folder (for example
`C:\work\Culsans_replication`) and run:

```
vivado -mode batch -nojournal -source synth/synth_culsans.tcl
```

This creates the authors' Xilinx IPs (clock generator, DDR3 controller, AXI converters, GPIO, SPI, ILA),
reads the FPGA file list (`build/filelists/culsans_fpga.tcl`) and synthesizes `culsans_xilinx` for the
Genesys 2 part (xc7k325tffg900-2) at the authors' 50 MHz. Add `-tclargs impl` to also place and route
(no bitstream), and `authors` to use their exact synthesis settings (flattened netlist with retiming; can take many hours on a PC). Reports land in `build/fpga/reports/`; `summary.txt` lists LUT/FF/BRAM/DSP for the CCU,
each core, the caches, the LLC and the crossbar. Expect 1 to 3 hours for synthesis.

## Simulate with Verilator (optional, faster)

Verilator 5.030 or newer is needed (Ubuntu 24.04's 5.020 cannot elaborate the LLC).

```bash
make verilator                                        # about 4 minutes
make run HEX=build/sw/integration/read_cache_share.hex
make regress                                          # all integration tests, 4 in parallel
```
